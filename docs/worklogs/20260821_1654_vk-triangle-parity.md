# Headless Vulkan-vs-software triangle rasterizer

## Goal
A real Vulkan graphics-pipeline triangle path, compared byte-for-byte
against `gpu_render_triangle` for the three existing parity cases, with
no SDL2.

## Done
- `vk/raster.c` draws a fullscreen triangle and runs PS1 coverage,
  barycentric shade, 4x4 dither, BGR555, and semi-transparency in the
  fragment shader. It does not call `gpu_render_triangle`.
- SPIR-V is generated by `vk/shaders/gen_spv.py` (no glslang on this
  host) into `vk/shaders/tri_shaders.inc`.
- `tests/vk_vram_blit.c` still does the VRAM buffer copy, then independently
  rasterizes flat / shaded-dithered / semi-transparent on software and
  Vulkan and `memcmp`s 2 MiB VRAM.
- Source check requires `vkCreateGraphicsPipelines`, `vkCmdDraw`, and
  forbids `gpu_render_triangle` inside `vk/raster.c`.
- Software GP0 path is still `frontend/gpu_hw.c:65`.

## Broken / Known issues
- Haswell ANV cannot create a graphics pipeline at all, so pixel
  agreement of the new shader vs software is NOT VERIFIED on this
  machine. A device that can create the pipeline must memcmp; mismatch
  is a fail.
- No swapchain / WSI.
